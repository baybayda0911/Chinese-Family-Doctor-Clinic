# 产品与实施决策

基线日期：2026-10-11。本文是产品约定，不保存私人访谈对话或真实家庭资料。

- 平台与组织：Codex本地主入口＋六室按需模块＋共享规则；先支持中国大陆中文环境。
- 人群：成人、老人、儿童、孕妇的日常管理；需专业判断的场景转相应专业人员。
- 职责：信息整理、风险提示、就医准备和长期管理，真实诊断/处方由执业人员承担。
- 三条首版流程：症状与分流、报告整理、慢病/日常管理。多格式文字/Word/图片/各类PDF是首版硬要求。
- 资料处理：本地解析/OCR→脱敏→人工核对→模型必要片段。原始身份资料不先交模型处理。
- 档案：成员独立JSON主数据、Markdown派生视图，真实档案与源码分离；档案室统一写入。
- 确认：每次新增/更正集中确认一次，重大后续变更新建批次；原始事实、用户自述、医生记录、AI分析分型。
- 协作：导诊、范围、主责、必要协作、汇总、归档随访；任一阶段保留危机中断。
- 观点冲突：保留出处/局限，安全冲突暂停相关干预并由专业人员复核。
- 外部检索：允许公开官方/可靠资料，搜索仅通用主题，原件不送第三方解析。
- 随访：先有来源、日期、负责人明确的清单；提醒是后续启用并配置的扩展。
- 双设备：各有本地库，同成员一个主库，人工交换已授权摘要；当前不建设复杂权限系统，预留授权/隔离/自助接口。
- 默认私密：按成员和信息范围共享；心理/生育等敏感细节不默认进家庭汇总。
- 文化：家庭室自选“命理风水咨询”，仅主动启用，独立记录，不参与医学决定。
- 上游：Yungho为主要架构参考；TCM.Skill为中医主参考、nihaixia为可选流派，family-doctor-zh的准确来源为yiyanli123/family-doctor-skills；按分层许可适配部分工作流，其余知识资料外置。
- OCR：先核查Codex插件/既有本地工具，必要时调查GitHub开源路线；本地MCP也需脱敏/核对处理层。
- 验收：虚构案例先行，功能与资料识别、医学规则复核、隐私处理、临床验证分别记录。
- 本次范围：实施基线文件及校验；完整首版原型、两机部署和真实健康资料使用在后续任务实施。
- 仓库：Chinese-Family-Doctor-Clinic，主框架保留远程已有MIT，第三方内容分别保留许可；每个项目独立Git管理，不把本地构建自动扩大为发布。
